# 주행 분석 · 피드백 · 맞춤 퀘스트 추천

브랜치 `feature/driving-analysis` (기준: `refactor/chageun-product-ui`). 실제 차량 주행 기록을 분석해 점수를 매기고, 피드백 문장을 만들고, 여러 번의 주행에서 반복되는 약점으로 퀘스트를 추천한다.

## 흐름

```
VehicleQuestController ── 1초 속도 샘플 ──▶ Room (TripSample)
        │ (깜빡이·조향각·브레이크 → 기존 차량 신호 퀘스트 시도)
        ▼
SharedCoachRepository.buildReport
        ├ DrivingAnalyzer   → TripEvent(심각도) + TripReport.skillScores
        └ FeedbackWriter    → TripReport.headline / goodPoints / practicePoints
                                   │
QuestRecommender  ◀── 최근 5번 VEHICLE 주행의 점수 + 메모 + 차량 신호 퀘스트 진행
        ▼
퀘스트 화면 "맞춤 추천" 탭, 피드백 화면 "맞춤 퀘스트" 버튼
```

| 파일 | 하는 일 |
|---|---|
| `analysis/DrivingAnalyzer.kt` | 급출발·급가속·급감속(팀 `SpeedReview` 기준) + 심각도 1~3 + 3초 병합, 기술별 점수 |
| `analysis/FeedbackWriter.kt` | 한 줄 요약, 잘한 점, 연습할 점(근거 숫자 포함). 운전자 메모를 맨 앞에 |
| `analysis/QuestRecommender.kt` | 약점 판단과 퀘스트 최대 3개 추천, 진행도 계산 |
| `ui/RecommendationCanvas.kt` | "맞춤 추천" 화면 |
| `core/data/SharedCoachRepository.kt` | 리포트 생성에 위 분석 연결, `recommendations()`, `scores()` |
| `session/VehicleQuestController.kt` | 속도만 있어도 주행 기록, 출발 직전 정차 값을 첫 샘플로 |

세 분석 파일은 Android 의존성이 없는 순수 Kotlin이라 `analysis/*Test.kt`로 PC에서 테스트한다.

## 점수 (0~100, 측정할 수 없으면 "—")

| 기술 | 계산 | 측정 조건 |
|---|---|---|
| 부드러운 출발 | 100 − (급출발·급가속 심각도 합 × 8) | 속도 샘플 30초 이상 |
| 여유 있는 감속 | 100 − (급감속 심각도 합 × 8) | 속도 샘플 30초 이상 |
| 깜빡이 먼저 켜기 | 차량 신호 퀘스트 성공 비율 (판정 보류·브레이크 문제 제외) | 시도 1번 이상 |
| 회전 전 감속 | 우회전 시도 중 브레이크를 밟은 비율 | 브레이크 값이 있는 우회전 1번 이상 |

- 심각도: 가속 +10/+13/+16 km/h/s, 감속 −12/−15/−18 km/h/s 이상이면 1/2/3단계
- 샘플 간격이 1.5초를 넘으면 그 구간은 판단하지 않는다(팀 `SpeedReview` 규칙 유지).
- 2분 미만 또는 1km 미만 주행은 "짧은 주행·참고용"으로 표시하고 추천에서 가중치를 절반으로 둔다.
- 자동 시연(REPLAY) 기록은 점수를 매기지 않고 팀의 기존 문구를 유지한다.

## 추천 기준

약점 (하나라도 해당하면):
- 가중 평균 점수 < 70 (최근 주행일수록 가중치 1.0, 0.8, 0.6, 0.5, 0.4)
- 최근 5번 중 3번 이상 70점 미만
- 같은 분류의 메모 2건 이상 (차로 변경→깜빡이, 우회전→회전 전 감속, 속도 조절→감속, 좌회전·유턴·주차는 메모만으로)
- 점수가 있는 주행이 3번 미만이면 평균 < 60일 때만 점수 약점으로 본다.

우선순위 = (70 − 평균) + 메모 수 × 10 + 70점 미만 횟수 × 5, 높은 순서로 최대 3개.

| 약점 | 추천 퀘스트 | 유형 | 진행 |
|---|---|---|---|
| 부드러운 출발 | 3초 세며 천천히 출발하기 | 다음 주행에서 자동 확인 | 최근 주행부터 100점 연속 2번 |
| 여유 있는 감속 | 앞차와 3초 거리 두기 | 다음 주행에서 자동 확인 | 최근 주행부터 92점 이상 연속 3번 |
| 깜빡이 먼저 켜기 | 차선 변경 · 깜빡이 먼저 | 차량 신호 퀘스트 | 기존 퀘스트 보드 진행 (x/30) |
| 회전 전 감속 | 교차로 우회전 · 감속 먼저 | 차량 신호 퀘스트 | 기존 퀘스트 보드 진행 (x/30) |
| 좌회전·유턴·주차 메모 | 장소 연습 제안 | 연습 장소에서 직접 | 진행 추적 없음 |

추천은 저장하지 않고 화면을 열 때마다 다시 계산한다. 리포트·메모·퀘스트 진행이 바뀌면 바로 반영된다. 기존 `Quest` 테이블 행 수는 바뀌지 않는다(팀 계측 테스트 기대값 유지).

## 에뮬레이터 확인 (2026-11-14, Pleos Connect v2.1.0)

- Virtual Console로 약 5분 주행(급가속 1·급감속 3 입력) → 1초 샘플 322개 저장, 급가속 1·급감속 2 감지(나머지 1번은 샘플 간격 2.5초라 판단 제외), 점수 출발 76 / 감속 52
- "맞춤 추천" 탭: 평균 점수 표시, 감속 52점 → "앞차와 3초 거리 두기" 추천(0/3)
- 피드백 화면: 요약·점수·잘한 점·연습할 점 표시
- 미확인: 출발 직전 정차 값을 첫 샘플로 남기는 보완(급출발 감지)은 단위 테스트 없이 코드로만 반영. 두 번째 주행에서 에뮬레이터가 심하게 멈춰(샘플 간격 2~24초) 확인하지 못함
