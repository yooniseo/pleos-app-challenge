첨부한 01_세션컨텍스트.txt와 02_이관상태.json을 먼저 읽고, 집 PC에서 이전 작업을 이어서 진행해줘.

저장소: https://github.com/yooniseo/pleos-app-challenge
작업은 scratch/driving-guide에서만 해줘. main, scratch/quests, scratch/gain은 수정·병합·이름 변경하지 마. 기존 작업은 지우지 마.

Figma 기준 3번은 “쉬운 주행·주차 안내”, 1번은 퀘스트, 2번은 주행 피드백이고 그 브랜치는 scratch/gain이야. 번호를 바꾸거나 퀘스트를 다시 개발하지 마.

기본 주행·주차 코치와 퀘스트/피드백 연결 틀은 이미 구현됐어. 지금 할 일은 정상적인 Pleos 환경에서 실제 SDK 값 수신을 확인하고 필요한 부분을 고치는 거야. 시나리오는 같은 교차로에서 우회전을 위한 오른쪽 차로 준비 → 우회전 → 그 교차로 빠져나오기야.

이전 PC에서는 부팅·APK 설치·SDK 초기화 요청까지 확인했지만, 에뮬레이터 기본 서비스 반복 종료와 Virtual Console 503 때문에 실제 값 수신은 검증하지 못했어. 데모나 빌드/단위 테스트 성공을 실제 API 검증 성공으로 말하지 마.

먼저 집 PC의 저장소/브랜치/작업물과 Pleos 환경을 확인해줘. docs/experiments/driving-guide/HANDOFF.txt와 runtime-probe.md를 읽고, 엄격한 실제 콜백 검증부터 재개해줘. 방향지시등 조회·구독, 속도, 실제 내비 TBT, Pleos TTS 재생 시작·완료를 각각 수신 값과 로그로 확인해줘. 빠진 항목은 미검증/미지원/실패로 분명히 구분해줘.

실제 자동 깜빡이 setter는 현재 Vehicle 2.3.2 공개 API에 없어. 앱 내부 시뮬레이션을 실제 차량 제어처럼 표현하거나 제조사 전용 권한을 우회하지 마.

추가 파일의 소스변경백업.patch는 Git 최신 커밋을 정상적으로 받았다면 적용하지 마. 기존 작업과 main을 보존하면서 이관상태 JSON의 코드 상태부터 이어가면 돼.
