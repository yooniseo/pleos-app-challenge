# 운전석 조작 체험 (2026-11-12)

`scratch/driving-guide`에 운전자가 직접 조작하는 네이티브 화면을 추가했다. 바탕화면 작업 폴더의 `운전석 체험.cmd` 또는 코치 상단 `운전석 체험` 버튼으로 연다.

## 코치를 켠 채 동시에 조작하기

바탕화면의 `주행코치+시뮬.cmd` 또는 기존 `운전석 체험.cmd`를 실행한다. 왼쪽은 주행 코치, 오른쪽은 운전석 조작판이다. 좁은 화면에서는 두 영역을 위아래로 배치한다. 두 영역은 독립 스크롤이 가능하며 하나의 DrivingSimulator 상태를 공유한다.

- 조작판에서 바꾼 기어/깜빡이/페달/핸들 입력이 코치의 현재 상황·남은 차로 수·안내·차량 위치에 반영된다.
- 코치의 다시 듣기/음성 켜고 끄기/이 순간 기억을 사용할 때 시뮬레이션을 멈추지 않는다. 기억한 순간은 체험 피드백과 기존 코치의 최근 운전석 리포트에 포함한다.
- 창 밖으로 전환되거나 OEM 카메라가 앞으로 나오면 기존처럼 정지한다. 코치와 조작판 사이에서 클릭하는 것은 화면 전환이 아니다.
- 주행 시 코치와 조작판이 모두 보이고, D단 SDK 속도가 들어오는 동안 코치 메모를 눌러도 이동이 계속되는 것을 cockpit_probe에서 검사한다.

이 코치는 **동일한 가상 시나리오의 입력을 받는 체험용 코치**다. 실주행용 코치의 승인 범위와 OEM 내비 보조 정책은 [주행 중 사용 요건](driving-availability-2026-11-12.md)의 미해결 항목으로 남는다.

## 자동 시연과 멈춤 상태 안내

상단 `자동 시연 시작`은 선택한 좌/우 시나리오를 **처음부터** 재생한다. 가상 벨트·브레이크·기어·방향지시등·미러 확인·핸들·페달을 순서대로 입력하고, 정지선에서 가상 빨강/보행자 상황을 기다린 뒤 조건을 바꿔 회전한다. 두 차로 이동과 마지막 P단/주차 브레이크/주변 확인까지 자동 진행한다. 실제 차량을 운전하는 제어기가 아니다.

- `일시정지` / `계속하기`로 재생을 멈추고 이어간다. `자동 시연 멈추기`는 차량 모형을 멈추고 수동 모드로 전환한다.
- 오른쪽 핸들·페달·기어 등 직접 운전 입력을 사용하면 자동 시연이 해제된다. 코치의 듣기·메모 조작은 자동 시연을 해제하지 않는다.
- 자동 재생 중 깜빡이는 앱 모형에 표시하고 Virtual Console에는 OFF를 보낸다. OEM 카메라 자동 전환이 재생을 중단하는 것을 피하기 위한 개발용 동작이며, SDK가 실제 깜빡이 점등을 확인했다고 표현하지 않는다. 수동 모드의 기존 실제 콘솔 입력은 유지한다.
- 일시정지 중에는 기존 단계 지시 대신 큰 재개 안내와 인라인 `▶ 계속하기` 버튼을 표시한다. 대기 중 액셀 입력도 ‘계속하기 후 적용’으로 표시한다.
- 주변 확인은 자동 출발 입력이 아니다. 수동 모드에서는 브레이크·기어·벨트·주차 브레이크 또는 액셀 미입력으로 이동하지 않는 이유를 코치 아래에 설명한다.
- 단위 검사에 도로 표시를 따르는 좌/우 두 자동 시나리오 완주, 가상 신호/보행자 대기 순서, 비 오는 출발 및 이동 대기 이유를 추가했다. `auto_probe=1`은 실제 실행 경로로 끝까지 자동 시연하고 재개 안내·수동 전환·종료 시 P단 복귀를 검사한다.
- 도로 개편 전 자동 시연 검증은 76개 검사 및 15개 단계 기준이었다. 아래 도로 개편 검증으로 대체한다.

```powershell
adb -s emulator-5574 shell am instrument --user 10 -w -r -e auto_probe 1 com.hmgchallenge.pleosstarter.test/com.hmgchallenge.pleosstarter.driving.CoachSmokeRunner
```

## 조작과 시나리오

- 드래그 가능한 핸들 이미지, 현재/목표 각도, ±15° 및 가운데 복귀, 각도 슬라이더.
- 액셀/브레이크는 한 번 클릭하면 유지되고 다시 클릭하면 해제된다. 다른 페달을 선택하면 기존 페달은 풀리며 `페달 모두 떼기`로 둘 다 해제한다. 브레이크를 켜둔 채 기어·사이드브레이크를 마우스로 조작할 수 있다.
- P/R/N/D, 좌/우 깜빡이와 OFF, 사이드브레이크, 벨트, 창문, 와이퍼.
- 빨강/초록 신호, 보행자 접근, 비 오는 상황은 명시적으로 설정하는 체험 조건이다. 카메라 분석이나 안전한 진입 판정이 아니다.
- 후진 주차 상태에서 D단 전진 출차 → 출구 횡단보도 앞 정차 → 보호 신호·보행자 확인 → 본선 진입 → 한 차로씩 두 번 변경 → 사거리 정지선 앞 정차 → 신호·횡단보도 확인 → 지정 차로에서 회전 → 나가는 쪽 횡단보도 통과 → 가상 체험 종료.
- 우회전 연습: 북쪽 주차장 출구에서 보호 좌회전하여 본선 1차로 진입 → 1→2→3차로 → 3차로 우회전. 좌회전 연습: 남쪽 출구에서 우회전하여 3차로 진입 → 3→2→1차로 → 1차로 좌회전. 도로 표시와 반대되는 두 조합은 제거했다.
- 깜빡이가 꺼져 있거나 반대면 해당 방향 점등 안내를 표시한다. 차로마다 미러 확인을 다시 입력하고, 한 차로 완료할 때 남은 개수가 줄어든다.
- 빨강 또는 보행자 접근 설정에서는 교차로 회전 단계로 넘어가지 않는다. 움직이는 동안 P/R/D 전환이나 주차 브레이크 조작은 이 체험에서 거부한다.

차량은 저속 bicycle kinematic model로 이동한다. 조향 입력이 실제로 모델의 위치/방향/이동 궤적을 바꾼다. 도로 그림은 가상 훈련 도로이며 OSM 실지도 화면과 구분한다. 실선은 직접 조작한 궤적, 점선은 공유 도로 좌표에서 만든 연습 경로다.

축거 2.75m, 조향비 14.5:1을 가정했다. 본선 차로 폭은 3.5m, 우회전 경로 반경은 8m, 좌회전은 18m다. 목표 핸들각은 현재 위치에서 경로를 바라보는 pure pursuit 방식으로 매번 계산한다. **실차 조향각 안내로 보정된 값이 아니다.**

## 도로 구조 개편

`TrainingRoadLayout`의 미터 좌표를 렌더링·경로·단계 판정이 공유한다. 왕복 6차로 사거리, 이중 황색 중앙선, 양방향 흰 차선, 접근부 실선, 좌/직/우 차로 화살표, 네 방향 횡단보도와 정지선, 둥근 모퉁이를 표시한다. 별도 주차장 출구에도 횡단보도와 정지선을 둔다. 반대편 차량과 교차 방향 차량은 분리된 차로에 배치하고 가상 보호 신호에서 기다리게 한다. 신호와 보행자는 작성한 가상 상황이며 실시간 교통 인식이 아니다.

회전은 헤딩만 바꿨다고 완료되지 않는다. 실제 차체 위치가 올바른 회전 차로에 있어야 시작하고, 같은 좌표의 회전 경로를 따라 나가는 쪽 횡단보도를 통과해야 완료된다. 차로 변경도 각 차로 중심에 도달해야 개수가 줄어든다. 정지선을 넘으면 다시 연습하라는 안내를 표시한다. 종료 시 P단은 시뮬레이터 정리 동작이며 실제 주차/하차 퀘스트를 적립하지 않는다.

이 도로는 특정 장소를 측량한 복제본이 아닌 가상 시가지다. 본 도로의 표시에서 우회전은 가장 오른쪽인 3차로, 좌회전은 1차로로 설정했다. [도로교통법 제25조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1030975005)의 우회전 전 도로 우측 가장자리 접근 원칙을 반영했다. 실제 도로의 회전 가능 차로는 해당 현장 표지·노면 표시를 따른다.

모델 근거: [MathWorks bicycle kinematics equations](https://www.mathworks.com/help/robotics/ug/mobile-robot-kinematics-equations.html).

## Pleos와 연결되는 부분

| 조작 | 연결 |
|---|---|
| D/N/P, 가속·브레이크·속도·조향, 깜빡이, 앞좌석 왼쪽 창문, 앞 와이퍼 | 개발용 Pleos Virtual Console의 로컬 입력 API로 발행 |
| 속도 및 깜빡이 피드백 | 별도의 AAOS/Pleos SDK 콜백으로 재확인하여 화면 아래 표시 |
| R단 후진 이동 | 시스템 후방카메라가 조작 화면을 차지하므로 앱 모델에서 진행. 이 구간 에뮬레이터는 P/0km/h 유지 |
| 벨트, 주차 브레이크, 주변 확인, 신호/보행자 | 앱 모델의 체험 입력. 실제 차량 상태를 바꿨다고 표현하지 않음 |

블링커를 보내면 OEM 사각지대 카메라가 자동으로 열린다. 화면 전환 시 모형을 멈추고, 카메라를 뒤로 닫아 돌아온 후 `계속하기`로 진행한다. OEM 카메라나 차량 경고를 비활성화하지 않았다.

Virtual Console 연결은 debuggable APK + `ranchu/goldfish` 하드웨어에서만 허용한다. 물리적인 Automotive 기기에서는 이 조작 화면 자체를 거부한다. 개발 APK의 이 화면에만 테스트 입력용 distractionOptimized 메타데이터를 선언했다. release에는 이 선언이 없다. 평문 네트워크 예외는 `127.0.0.1`만 허용한다. 실제 차량의 가속·브레이크·기어·조향 actuator SDK로 구현한 기능이 아니다.

화면을 닫으면 0km/h·P단·깜빡이 OFF 입력을 보내고, 창문/와이퍼는 시작할 때의 상태를 복원한다. 시스템 카메라 등으로 잠시 가려지면 즉시 모형을 정지한다.

## 퀘스트·피드백

단계별 짧은 피드백과 Pleos TTS 안내를 사용한다. `피드백` 버튼과 기존 `주행 피드백` 화면에서 최근 운전석 체험을 볼 수 있다. 확인한 출발/차로 변경/교차로 경험은 `QuestEngine.recordPractice`를 통해 **시연 프로필에만** 저장한다. 한 번의 체험에서 같은 skill은 중복 적립하지 않는다. 개인 프로필이나 실차 수행 경험으로 처리하지 않으며, 직접 차로 변경했다고 입력한 기존 시나리오와 구분되는 운전석 체험 리포트를 저장한다.

## 검증

- 도로 개편 후 단위 검사 80개, assembleDebug, assembleDebugAndroidTest, lintDebug 통과.
- 확대된 화면의 에뮬레이터 자동 시연 `PASS_AUTO_PLAYBACK`: 17개 단계 완료, 실제 위치 3차로에서 우회전, 진입/진출 횡단보도 통과, 정지선 앞 차체 정차, SDK 속도 수신, 일시정지·수동 전환·종료 후 P/0km/h 확인. 증거는 바탕화면 `output/road-realism-2026-11-12`에 저장했다.
- 도로 개편 단위 검사: 좌/우 자동 완주, 두 번의 차로 중심 도착, 신호/보행자 대기, 실제 위치가 잘못된 차로일 때 회전 거부, 정지선 앞 차체 정차, 진입/진출 횡단보도 통과, 전체 이동 중 차체 네 모서리가 포장 도로 안에 있는지 검사한다.
- assembleDebug, assembleDebugAndroidTest, lintDebug 통과.
- `cockpit_probe`: PASS_COCKPIT_CONTROLS. UI 입력으로 창문 50%, 와이퍼 LOW, 핸들 45°, 왼쪽 깜빡이, D단 가속 45%, 실제 SDK 속도 1.388889m/s(5km/h)와 LEFT 응답을 받았다. OEM 카메라에서 뒤로 돌아와 재개했으며, 종료 후 P/0km/h/OFF를 확인했다. 후진은 앱 모델 2.77m 이동으로 별도 검증했다.
- 테스트 전 시연 프로필/최근 리포트를 복원하고 개인 프로필이 바뀌지 않는지 검사한다.

```powershell
adb -s emulator-5574 shell am instrument --user 10 -w -r -e cockpit_probe 1 com.hmgchallenge.pleosstarter.test/com.hmgchallenge.pleosstarter.driving.CoachSmokeRunner
```

바탕화면 `output/map-vehicle-integration-2026-11-12`에 `cockpit-proof.json`과 화면을 저장했다. 기본 내비의 흰 배경, 참고 경로와 OEM 경로의 차이, 휴대폰 미구현 등은 [지도/기획 비교](map-vehicle-2026-11-12.md)를 참고한다.

## Figma 지도 UI 적용

Figma `Sqpacf0pJmLc2RNnZBUrqo`, `73:10511`을 기준으로 기본 시뮬레이터 화면을 지도 중심으로 바꿨다. 초록 회전 카드, 다음 진행 카드, 차로 화살표, 파란 현재 위치, 하단 목적지 영역과 Asta Sans를 네이티브로 구현했다. Figma 원본 SVG와 현재 위치 PNG를 로컬 자산으로 사용한다. 컴포넌트 PNG 내보내기에 회색 배경이 포함돼 원본 SVG를 AndroidSVG 1.4로 렌더링했다. 지도·경로·거리·현재 속도·차로는 동적 데이터이며 정적인 화면 캡처를 앱 배경으로 쓰지 않는다.

- 지도는 OpenStreetMap 타일과 기존 캐시 로더를 재사용한다. CARTO Voyager 공개 주소는 이 환경에서 API KEY REQUIRED 이미지를 반환해 사용하지 않는다. 지도 위에 OSM 저작자 표시를 유지한다.
- 경기대 후문 인근 창룡대로 → 대학로의 OSRM 경로 192.2m를 로컬 fixture로 보관한다. 실제 도로 형상을 따라 표시하며 사용자의 GPS나 OEM 내비 경로라고 표현하지 않는다.
- `NavigationSimulationRoute`는 기존 단계/조향 모델 진행도를 도로 경로에 대응시킨다. 차로 변경의 횡방향 오프셋과 파란 예상 경로가 함께 바뀐다. 회전 단계는 도로 곡선을 따라 위치와 방위각을 갱신한다. 이 대응은 시연용 투영이며 실차 주행 물리/차로 정밀 위치로 보정한 것이 아니다.
- 지도 자동 시연은 본선부터 시작하며 가상 벨트/D단을 준비한다. 기존 출차 연습·창문·와이퍼·핸들·페달은 `운전 조작`에서 유지한다. `지도 보기`로 돌아오며 한 Activity의 상태를 공유한다. 지도 연습은 우회전용이고 기존 좌회전 조작 연습은 별도로 유지한다.
- 현재/목표 차로와 남은 횟수, 정지선·가상 보행자 대기, 회전 안내, 기억/음성/퀘스트를 같은 모델에 연결한다. 실제 차로 인식으로 표현하지 않으며 화면에도 가상 3차로 연습으로 표시한다.
- 디자인의 단속카메라/교통 혼잡 예시값은 실제 정보가 없어 노출하지 않는다. 해당 영역은 저속 연습 속도와 체험 진행률로 사용한다.
- 단위 검사 83개 및 빌드/Lint 통과. `navigation_probe=1`: PASS_FIGMA_NAVIGATION. 실제 타일 표시, 차량 위치 이동, 1→2→3차로, 회전/완료, 일시정지 지도 고정, 조작판 왕복, 실제 SDK 속도 수신, 종료 후 P/0km/h 및 개인 프로필 유지 확인.

## 지도 시연 중 주행 차단 재발 수정

지도 시연이 실제 에뮬레이터 입력을 D/6km/h로 바꾸던 상태에서 주차 전용 코치로 전환되면 OEM 차단 화면이 나타났다. 지도 화면과 자동 시연은 이제 차량 입력 P/0km/h를 유지하며 앱 내부의 차량·지도·경로를 움직인다. 화면의 속도는 앱 모형의 속도다. 수동 운전석의 기존 콘솔 입력 연동은 별도로 유지한다. 자동 시연의 실제 SDK 속도는 0으로 검증하고 앱 모형 이동은 별도로 검증한다.

시뮬레이터 자동 진입은 코치 onStart의 지연 작업에서 onResume으로 옮겼다. 이전에는 화면이 잠시 가려지면 진입 요청을 소모하고도 열지 못할 수 있었다. 실행 스크립트의 Cockpit 강제 종료(-S)도 제거했다. 개발용 DO 선언과 release 주행 제한은 변경하지 않았다. **이 수정은 정차 상태의 지도 시연을 위한 것이며 실차 주행 중 사용 승인 완료를 의미하지 않는다.**
