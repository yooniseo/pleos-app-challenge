# 퀘스트·성장·안내 설정 — 구현 및 실행

작업 브랜치: `scratch/quests`. **main과 기존 MainActivity는 변경하지 않습니다.** 기존 ‘나의 드라이브’ 샘플과 별도로 ‘튜토리얼 · 퀘스트’ 런처를 추가했습니다. 기존 Kotlin/Android View 구조와 라이브러리 버전을 유지합니다.

## 합의한 방향

- 이 문서의 역할 이름은 **퀘스트 / 주행 코치 / 회고**입니다. 대화의 3번=퀘스트, 1번=주행 코치이며 Figma 프레임 번호와는 순서가 다릅니다.
- 기본 상황은 **같은 교차로에서 우회전을 준비하는 오른쪽 차로 변경 → 우회전 → 그 교차로 빠져나오기**입니다. 별도의 다음 교차로 직진이 아닙니다. 4차선/4지 교차로의 도로 형상을 SDK로 확인했다고 표시하지 않습니다.
- 모든 영역의 진척도는 함께 쌓습니다. 오늘의 집중 목표 하나는 학습 초점이며 다른 영역의 기록을 막지 않습니다.
- 영역별 동그라미 네 개는 **1~4단계 퀘스트 완료 상태**입니다. 자신감 점수나 단순 주행 횟수 표시가 아닙니다.
- 안내를 제공한 사실, 관측값, 수행 확인, 어려움, 미확인·건너뛰기·취소를 구분합니다.
- 어려움을 솔직히 남겨도 이미 확인한 경험이나 진척도가 줄어들지 않습니다. 어려움은 다음 추천에 반영합니다.
- 코칭 축소는 사용자가 선택하며 언제든 복구할 수 있습니다. 차량 자체 경고와 기본 내비게이션은 제어하지 않습니다.

## 실행 흐름

1. Android Studio에서 이 브랜치를 열고 app을 빌드·설치합니다.
2. **튜토리얼 · 퀘스트**를 엽니다. 기본 시연 기록과 ‘내 연습 기록’은 서로 다른 저장소입니다.
3. **퀘스트 · 성장**에서 영역의 1단계를 열어 준비 내용을 확인합니다.
4. **1번 연결 틀**에서 새 주행 시작 → 차로 변경 진입 → 수행 확인 → 우회전 진입 → 수행 확인 → 교차로 출구 진입 → 수행 확인 → 주행 종료를 누릅니다.
5. 같은 교차로의 우회전과 출구 확인은 **한 번의 교차로 경험**으로 합쳐집니다. 차로 변경 경험도 별도로 기록됩니다.
6. 관측값만 전달하면 경험이 늘지 않습니다. 어려움·확인 데이터 없음·취소·건너뛰기 버튼도 비교합니다.
7. **안내 설정**에서 차로 변경을 간략히, 교차로를 자세히로 설정하고 연결 틀에서 설정 전달을 확인합니다.
8. 서로 다른 시연 주행으로 경험을 추가하면 다음 단계 퀘스트가 완료됩니다. 4단계 경험 정리 후 코칭 줄이기를 직접 선택합니다.

이 화면은 **주차 상태의 학습·설정·연결 확인용**입니다. Automotive의 UX 제한이 걸리거나 상태를 확인하지 못하면 상세 화면을 잠급니다. 주행 코치 개발자가 실제 주행용 화면을 만들 때는 별도의 적합한 호스트에서 공유 인터페이스와 읽기 전용 `QuestStatusView`를 사용할 수 있습니다.

### 단계별 퀘스트 내용 — 조정 가능한 제안

Figma에는 네 칸의 의미는 있으나 각 칸의 세부 조건이 확정돼 있지 않아 아래를 초기값으로 제안했습니다. 숫자는 `StageQuestCatalog`에서 바꿀 수 있습니다.

1. **준비 내용 확인:** 해당 영역의 학습·확인 순서 살펴보기.
2. **첫 경험:** 서로 구분되는 확인된 연습 경험 1회.
3. **다시 해보기:** 확인된 경험 누적 3회. 동일 발생·증거 재전송은 추가되지 않음.
4. **내 경험 정리:** 앞 단계를 마친 뒤 경험과 다음 연습 방향을 글로 남김.

직접 확인은 개인 기록에서 같은 영역에 대해 하루 한 번만 누적합니다. 시연에서는 여러 번 재현할 수 있습니다. 어려움 메모는 경험을 차감하지 않습니다. 완료 비율에 따른 STARTER/DRIVER/MASTER 경계(35%, 75%)도 시연용 제안이며 운전 실력 인증 기준이 아닙니다.

## 1번은 연결 틀만 제공

`DrivingGuidePort` / `DrivingGuideHost` / `GuideUiModel`과 `PlaceholderDrivingGuide`를 제공합니다. 현재는 상황을 넣어보는 테스트 버튼뿐이며 **내비게이션·차량 센서 수집·운전 코치 알고리즘·TTS/STT·자동 점등은 구현하지 않습니다.**

다른 개발자는 `DrivingGuidePort`를 구현하고 `QuestActivity`의 `guide` 초기화 한 곳을 교체하면 됩니다. 별도 주행 화면을 사용할 때도 `QuestIntegration.observe()`와 `QuestStatusView`를 그대로 붙일 수 있습니다. [연결 규격과 예제](integration-contract.md)를 참고하세요.

## Figma·첨부 검토 내용 반영

[원본 보드](https://www.figma.com/design/UTgSBQztO4iDsnoTUyetPL/?node-id=0-1)의 한 페이지 전체 기능 영역, 공통 기획, 퀘스트 표 네 개, 주행·성장 이미지, 디스플레이 템플릿, 운영사 이메일 캡처를 검토했습니다. 출발 전·주차·주행 후 표가 퀘스트 프레임의 형제라는 점을 고려해 26개를 모두 읽었습니다. 연결된 Notion 내용까지 확인했다는 뜻은 아닙니다.

추가로 전달받은 Figma 검토문을 반영해 목표 선택과 동시 기록, 경험과 관측·자기평가 분리, 어려움 기록에 대한 불이익 방지, 안내 축소 선택권, assistanceUsed, 미확인·보류 상태, 텍스트 진척도·접근성 설명을 적용했습니다. 타 PC 경로의 캡처 파일을 읽거나 복사한 것은 아닙니다.

사진·회의 보드를 완성된 앱 화면으로 재사용하지 않았습니다. 기존 앱의 어두운 배경과 민트색을 재사용하고, 영역별 네 단계·전체 성장·설정 관계를 Android View로 구현했습니다. 전체 차량 화면 대신 앱이 사용하는 영역 안에서 크기에 맞춰 표시하며 시스템 계기·경고·하단 영역은 그리지 않습니다.

전화 자동 응답, 실제 차간거리·시선 측정, 카메라 주차 판단, 고정 핸들 회전 수 지시, 야간·눈·비 도전 자동 해금, 생체 신호, 차량 조명 효과, 캐릭터·사투리 음성, 모바일 연동·회피 경로는 이번 구현 범위가 아닙니다. 실제 데이터를 얻지 못하는 퀘스트는 센서 성공으로 표시하지 않고 직접 확인 또는 후속 구현 대상으로 남깁니다.

## 검증

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest
```

에뮬레이터 smoke test는 두 프로필을 백업·복원하고 시나리오 연결·설정 전달·단계·저장 복원·시연 분리·화면 캡처를 확인합니다. 실제 Pleos 값 수신을 검증하는 테스트가 아닙니다.

