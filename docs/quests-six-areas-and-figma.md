# 6개 퀘스트와 Figma 코치 컴포넌트

기준: [최신 Google 기획서](https://docs.google.com/document/d/1oH35z0IUnxPJ9NasQtq5Ntp_Z_xi-AcVDxOVCG4QS9M/edit), [Figma 스케치](https://www.figma.com/design/Sqpacf0pJmLc2RNnZBUrqo?node-id=42-5211).

## 시연 진행도가 보이지 않았던 원인

기존 DB에는 차선 변경 6회가 저장돼 있었다. 차량 신호 화면은 별도의 VEHICLE 보드만 표시했고, 기존 시연 막대는 학습 단계 완료를 계산해 0%로 남았다. 이제 시연 카드와 DB의 `demo:practice:SKILL` 행은 같은 `PracticeCompletion` 근거에서 진행도를 계산한다. 기존 근거 6개는 그대로 6/30으로 표시되며, 이전 학습 단계를 완료했다고 만들어내지 않는다. 30회마다 다음 레벨로 넘어가고 누적 횟수는 유지한다.

## 기획서의 6개 영역과 달성 조건

| 영역 | 이번 앱의 시연 조건 |
| --- | --- |
| 출발 준비 | 시작 전 점검 항목을 모두 직접 확인한 뒤 시연 시작. 점검 없이 시연을 선택하면 가산하지 않음 |
| 차선 변경 | 시나리오의 한 차로 이동 완료마다 1회. 전체 시연의 1→2→3차로는 2회 |
| 교차로 | 우회전 후 같은 교차로 이탈까지 마치면 1회 |
| 속도와 거리 관리 | 자동 전체 시연의 교차로 감속 구간 완료. 실제 차간거리 유지 성공으로 해석하지 않음 |
| 주차 | 후진과 정렬을 마치면 1회 |
| 하차 준비 | 주차 완료 후 하차 점검 항목을 모두 직접 확인하면 1회. 주차 전에는 기록 불가 |

전체 시연은 출발 점검 후 진행하면 주차까지 5개 영역을 기록하고, 하차 점검까지 확인하면 결과 화면이 6/6이 된다. 차선 변경 2회를 포함해 수행 근거는 7개이며, 기존 보상 규칙에 따라 600P다. 체크리스트는 같은 trip에서 반복해도 1번만 기록한다. 주차 전 CLEAR는 표시하지 않는다.

이 기록은 SIMULATION이다. 실제 SDK의 깜빡이·조향·브레이크 조건 보드는 계속 분리하며, 시연으로 실제 차량 진행도를 올리지 않는다. 출발·하차 체크리스트는 실제 안전벨트/주차 브레이크 센서 확인을 대신하지 않는다. 휴대폰 동기화와 실차 6개 영역의 자동 판정은 이번 변경에 포함되지 않는다.

## 디자인 적용

Figma의 캐릭터, 깃발, 느낌표, 지도 주의 표식, 스위치 ON/OFF, 이동 화살표를 개별 레이어로 내보내 로컬 PNG로 저장했다. Figma Plugin API의 `contentsOnly=true`로 주변 캔버스 배경을 제외했다. 배너 배경·문구·퀘스트 진행도와 클릭 동작은 Android Canvas / 네이티브 Button이다. 전체 화면 이미지를 붙이지 않았으며, 지도·차량·핸들은 기존 동적 렌더러를 유지한다.

에셋 원본 node ID와 크기는 `app/src/main/assets/figma/manifest.json`에 있다. 원본 Figma 파일은 수정하지 않았다. 지도 위 주의 표식은 가상 횡단보도 위치를 설명하며 실제 보행자 검출 결과가 아니다.

## 검증

`ProductSmokeRunner -e quest_design true`는 별도 `quest-design-validation.db`에서 차선 변경 6회 → 시연/차량 탭 비교 → DB 재개방 → 기존 6회 유지 → 출발 점검 → 전체 시연 → 주차 → 하차 점검 → 6/6 → 재개방을 검사한다. 사용자 `trips.db`와 설정을 초기화하지 않는다. Figma 컴포넌트 배치와 스위치 동작을 캡처해 확인한다. 기존 4개 시연 및 Pleos TTS, 차량 신호 퀘스트 검사도 유지한다.
