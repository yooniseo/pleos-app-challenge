# 5. 개발 계획

차근차근은 길을 알려주는 데서 한 걸음 더 나아가, 초보 운전자가 어려워하는 행동을 하나씩 익히도록 돕는 차량 연동형 운전 코치로 개발합니다. 같은 우회전 상황이라도 처음에는 확인 순서를 자세히 짚어주고, 익숙해지면 짧은 힌트만 제공하며, 충분히 연습한 뒤에는 운전자가 요청할 때 돕는 방식입니다. 운전자의 행동에 반응하고, 어려웠던 경험을 다음 코칭에 반영해 혼자 운전할 자신감을 키우는 것이 개발의 중심입니다.

## Pleos Connect 차량 앱 구현

차량 앱은 Kotlin과 Android Studio를 기반으로 Pleos Connect 환경에서 구현합니다. 차량 화면에는 지도와 경로, 현재 필요한 행동, 핸들 그림을 함께 보여주되 한 번에 확인할 정보를 줄입니다. 지도 위 차량 마커와 경로 진행에 차로 변경·회전 안내를 연결하고, 핸들 그림에서는 돌리는 방향과 복원 시점을 직관적으로 전달합니다. 정차 중 학습에서는 직접 핸들 그림을 조작해 따라 해보고, 목표에 맞으면 짧은 성공음으로 반응하는 기능을 제공합니다. 핸들 회전량은 차종과 도로에 따라 달라지므로, 고정된 조작량을 실차 운전 정답으로 제시하지 않습니다.

초기 시연은 짧은 차로 변경·우회전과 가상 연습장의 후진 주차로 범위를 좁힙니다. 자동 재생과 차량에서 받은 실제 속도에 맞춘 진행을 구분하고, 위치·차로·주차 과정이 시나리오인 부분을 명확히 표시합니다. 복잡한 조작과 학습 화면은 정차 상태에서 제공하며, 실제 주행 중 제공 가능한 화면과 음성은 Pleos의 운전자 주의 분산 정책 및 내비게이션 앱 요건을 확인해 적용합니다. 에뮬레이터에서 보이는 화면과 실차에서 승인된 기능은 구분해 검증합니다.

## 차량 상태에 반응하는 코칭과 SDK/API 활용

Vehicle SDK로 방향지시등, 안전벨트, 주차 브레이크 등 필요한 차량 상태를 항목별로 확인합니다. 이미 수행한 행동은 반복 안내하지 않고, 아직 확인하지 않은 행동을 중심으로 다음 단계를 제시합니다. 차량 속도는 현재 연결한 표준 AAOS Car API의 `PERF_VEHICLE_SPEED`를 사용하며, m/s 값을 km/h로 변환해 표시·저장합니다. 수신 시각과 유효성을 함께 관리해 값이 없거나 오래됐을 때 임의의 값으로 채우지 않습니다. Vehicle SDK의 지원 기능 조회와 권한 확인을 선행하고, 차종에서 제공하지 않는 항목은 운전자가 직접 확인하도록 안내합니다.

NaviHelper SDK는 경로 상태·회전 안내·위치 이벤트와 차량 내비게이션 연결에 활용합니다. 경로 변경이나 안내 종료가 발생하면 이전 안내를 중단하고 현재 상황을 다시 확인합니다. NaviHelper를 기본 내비게이션 지도 위에 임의로 화면을 올릴 수 있는 지도 SDK로 가정하지 않습니다. 현재 시연의 지도 경로와 실제 차량 내비게이션 이벤트를 구분하고, 실제 차로 수나 회전 연결 데이터를 확보한 구간에서만 구체적인 차로 안내를 제공하도록 확장합니다.

음성 출력에는 Pleos TextToSpeech SDK를 사용합니다. 짧고 친숙한 표현으로 방향과 확인 순서를 안내하고, 차량 안전 경고와 기본 내비게이션 안내가 코치 음성보다 우선하도록 구성합니다. SpeechToText SDK는 운전자가 남긴 어려움이나 메모를 텍스트로 바꾸는 데 활용합니다. 인식한 내용은 확인 가능한 형태로 저장하고, 서비스나 권한이 지원되지 않는 환경에서는 정차 중 글이나 버튼으로 기록할 수 있게 합니다. 현재 STT 연동 코드를 통합한 상태이며, 실제 인식 성공은 대상 환경에서 별도로 검증합니다.

## 퀘스트·피드백·다음 안내를 하나의 기록으로 연결

세 기능을 독립 화면으로 끝내지 않고 하나의 데이터 흐름으로 연결합니다. 주행이 시작되면 공통 주행 ID를 만들고, 속도 샘플·상황 이벤트·메모·연습 결과·리포트를 같은 ID로 저장합니다. Android Room 기반 공통 DB를 사용해 앱 재실행 후에도 기록과 설정이 유지되도록 합니다. 주행 안내에서 남긴 어려움은 종료 리포트와 복습에 연결하고, 다음에 같은 상황을 만났을 때 안내량을 결정하는 입력으로 사용합니다. 예를 들어 차로 변경 후 핸들 풀기가 어려웠다고 기록하면, 다음 연습에서는 그 순서를 다시 자세히 설명하는 방식입니다.

제품의 퀘스트 단계는 기술마다 STARTER·DRIVER·PRO·MASTER로 관리하는 방향입니다. 최근 성공률, 최소 경험 횟수, 서로 다른 주행일을 함께 보고 안내를 점차 줄이며, 안내가 완전히 꺼지는 졸업은 운전자의 확인을 받습니다. 도움을 다시 받아도 누적 성장 기록은 지우지 않습니다. 판정에 필요한 데이터가 누락되면 무효로 남기고, 시뮬레이션 결과와 실제 차량 기록을 분리합니다. 현재 시연은 기존 체험용 단계 엔진을 연결해 이 순환을 보여주며, 실차 성공률과 여러 날의 경험을 반영하는 제품 승급 규칙은 후속 개발 범위입니다.

## 차량 인터랙션과 주차 복습

차량용 앱의 특징은 ‘행동 → 차량의 반응 → 다음 연습’이 이어지는 경험으로 보여줍니다. 직접 핸들 연습을 수행하면 짧은 효과음을 제공하고, 주차나 연습을 마친 뒤에는 P단·정차·차량 지원 여부를 확인한 경우에만 실내 조명으로 축하합니다. 조명은 원래 상태로 복원하고, 해당 기능을 지원하지 않는 차량에서는 화면과 짧은 소리로 대체합니다. 주행 중 큰 팝업이나 조명 연출로 주의를 끌지 않습니다.

주차는 주변 확인, 시작 위치 이해, 후진 진입, 핸들 복원과 정렬, 마무리 점검의 작은 단계로 구성합니다. 초기에는 가상 연습장에서 원리와 조작 순서를 익히도록 구현하고, 실제 주차에서는 차량 기본 카메라와 센서 경고를 우선합니다. 주변 차량·보행자·사각지대·주차 공간을 확인할 수 있는 승인된 데이터가 없는 상태에서 ‘지금 이동해도 안전하다’고 판단하지 않습니다.

## 개발 순서와 검증

우선 각 브랜치의 주행 코치, 퀘스트, 속도·STT, Room 작업을 통합하고, 시나리오 시작부터 종료 리포트와 다음 안내까지 같은 DB로 이어지는지 검증합니다. 이후 최신 CASE ID 체계와 퀘스트 화면을 정리하고, 실제 API로 확인할 수 있는 출발·주행·주차·하차 항목부터 확장합니다. 마지막으로 계정과 서버 API를 마련해 차량의 리포트·복습·설정을 휴대폰에서도 이어보는 구조로 발전시킵니다. 휴대폰 연동은 현재 로컬 DB 연결과 구분되는 후속 범위입니다.

검증은 기능별 단위 테스트, DB migration·재실행 영속성 검사, Pleos 에뮬레이터 시나리오 검사로 나눕니다. 중복 성공 가산 방지, 개인 기록과 시연 기록 분리, 속도 누락 시 처리, 도움 요청 이후 안내 복원, 음성·조명 종료 및 원상 복귀를 확인합니다. 구현 완료·에뮬레이터 확인·실차 검증 예정 상태를 구분해 개발 결과를 관리합니다.
