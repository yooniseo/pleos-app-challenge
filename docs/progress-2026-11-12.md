## 1. 계획 줄이기

처음 계획에는 깜빡이 확인, 주차 실력 분석, AI 비서(Gleo) 연동 등 기능이 많았습니다. 일단은 **"속도"만으로 동작하는 최소 기능**

**남긴 기능**

- **운전 중**: "주행 시작" 버튼을 누르면 1초마다 속도를 기록합니다. 어려웠던 순간에는 메모를 남깁니다.
- **운전 후**: 속도 변화를 보고 **급출발, 급가속, 급감속**을 찾아 점수를 매기고 "잘한 점 / 연습할 점"을 보여 줍니다.
- **여러 번 운전한 뒤**: 자주 나오는 약점을 보고 연습 과제(예: "3초 세면서 천천히 출발하기")를 냅니다.

**뺀 기능** (시간이 남으면 다시 검토)

- 깜빡이 안 켜고 회전, 주차 실력 분석, 백그라운드 기록, 음성 안내, AI 비서 연동, 지도 표시 등

자세한 내용은 [driving-feedback-plan.md](driving-feedback-plan.md)

## 2. 개발 도구 설치

| 설치한 것 | 쉽게 말하면 | 상태 |
|---|---|---|
| Android Studio | 앱을 만드는 프로그램 | 완료 |
| Android SDK 34 | 앱을 만들 때 필요한 부품 상자 (Android 14용) | 완료 |
| Pleos 에뮬레이터 | 컴퓨터 안에서 돌아가는 **가상 자동차 화면** | 완료 (가상 기기 `Pleos_API_34` 생성, 실행 확인) |

## 3. 사전 점검

본격적으로 만들기 전에 "이게 정말 되는지" 두 가지를 확인하기로 했습니다.

| 점검 항목 | 결과 | 의미 |
|---|---|---|
| **V1. 차의 속도를 앱에서 읽을 수 있나?** | ✅ 통과 | 가상 자동차의 속도를 0→10→25→50→30→0 km/h로 바꿨더니 앱에 그대로 표시됐습니다. |
| **V2. 음성 인식(말하면 글자로 바꿔 주는 기능)을 쓸 수 있나?** | ✅ 통과 | **시속 30 km로 달리는 중에** "방금 비보호 좌회전이 어려웠어"라고 말하니 정확히 글자로 바뀌었습니다. 말로 메모하는 기능을 그대로 쓸 수 있습니다. |

**새로 알게 된 것**

- 앱에 "주행 중에도 써도 되는 앱"이라는 표시를 넣지 않으면, 차가 움직이는 순간 **"주행 중에는 사용할 수 없습니다"** 화면으로 막힙니다. 표시를 넣었더니 주행 중에도 잘 동작했습니다.
- 가상 자동차의 속도·브레이크·핸들 각도는 **웹 화면(Virtual Console)** 에서 바꿀 수 있습니다. 발표 때 급가속·급감속 장면을 이걸로 재현할 수 있습니다.

자세한 기술 기록은 [vehicle-sdk-notes.md](vehicle-sdk-notes.md)에 있습니다.

### 사용할 수 있는 차량 정보 (받은 권한 목록)

주최 측에서 받은 목록에 따르면 아래 정보를 앱에서 쓸 수 있습니다.

- **주행 관련**: 주행 거리·시간, 브레이크 페달을 밟았는지, 핸들을 얼마나 돌렸는지, 크루즈 컨트롤
- **안전 관련**: 타이어 공기압 부족, 안전벨트 미착용, 엔진오일·브레이크오일 경고 등
- **조명 관련**: 깜빡이(방향지시등), 전조등, 실내등 등

**주의할 점**

- 이 목록에는 "차 속도"가 없지만, 속도는 Android 기본 기능으로 읽으며 **실제로 읽히는 것을 확인했습니다(V1).**
- **깜빡이·핸들 각도·브레이크 정보도 쓸 수 있습니다.** 가상 자동차의 웹 화면에서도 이 값들을 바꿀 수 있어 테스트도 가능합니다. 그래서 뺐던 "깜빡이 안 켜고 회전" 기능은 기본 기능을 다 만든 뒤 **가장 먼저 추가할 후보**입니다.

## 4. 데이터 저장 공간 만들기

앱 안에 **엑셀 같은 표 6개**를 만들었습니다. 운전 기록, 분석 결과, 퀘스트가 모두 여기에 저장됩니다.

| 표 이름 | 무엇을 저장하나 | 언제 |
|---|---|---|
| Trip (주행) | 언제 출발하고 언제 끝났는지, 몇 km 달렸는지 | 운전 중 파트 |
| TripSample (속도 기록) | 1초마다의 속도 | 운전 중 파트 |
| DrivingNote (메모) | 운전자가 남긴 "어려웠던 순간" | 운전 중 파트 |
| TripEvent (위험 순간) | 급출발·급가속·급감속이 언제, 얼마나 심했는지 | 운전 후 파트 |
| TripReport (리포트) | 한 줄 요약, 잘한 점, 연습할 점, 점수 | 운전 후 파트 |
| Quest (연습 과제) | 과제 이름, 이유, 진행도 | 퀘스트 파트 |

세 파트(운전 중 / 운전 후 / 퀘스트)는 이 표를 통해서만 정보를 주고받기.

- 이 작업은 `chore/add-room`이라는 작업 공간(브랜치)에 저장.

## 5. 정해야 할 것

| # | 질문 | 추천 |
|---|---|---|
| 1 | ~~음성 인식을 못 쓰는데, 운전 중 메모는 어떻게 남기나요?~~ | **해결**: 음성 인식이 되므로 마이크 버튼으로 말해서 메모 |
| 2 | 발표 때 주행 장면을 어떻게 보여 주나요? | 가상 자동차의 **웹 화면(Virtual Console)으로 속도를 바꿔 가며 시연**. 가짜 데이터 재생 기능은 없어도 됨 |
| 3 | 리포트 문장을 AI(LLM)로 만들기로 계획서가 바뀌었는데, 어떤 AI를 어떻게 쓰나요? | 우선 **정해진 문장 틀**로 만들고, 시간이 남으면 AI로 다듬기 (AI는 인터넷 연결·API 키가 필요할 수 있음) |
| 4 | 데이터 저장 공간 작업을 팀 저장소에 올리고 검토를 요청할까요? | 올리고 바로 검토 → 합치기 (이게 합쳐져야 다른 파트가 시작 가능) |

## 6. 다음 할 일

1. 프로젝트를 영어 이름 폴더로 옮기고, Android Studio에서 JDK 17을 설정합니다.
2. 데이터 저장 공간 작업을 팀 저장소에 올리고 검토받아 합칩니다.
3. 세 파트가 동시에 개발을 시작합니다.
   - **운전 중**: 주행 시작·종료 버튼, 1초마다 속도 기록, 마이크 버튼으로 음성 메모
   - **운전 후**: 급출발·급가속·급감속 찾기, 점수, 리포트 화면
   - **퀘스트**: 약점 찾기, 과제 고르기, 진행도 표시
4. 기본 기능이 끝나면 브레이크·핸들 각도·깜빡이 정보를 이용한 기능(깜빡이 없이 회전 등)을 추가합니다.

## 용어 풀이

| 용어 | 뜻 |
|---|---|
| 에뮬레이터 | 컴퓨터 안에서 돌아가는 가상 기기. 여기서는 가상 자동차 화면 |
| SDK | 앱을 만들 때 쓰는 부품 모음. "Vehicle SDK"는 차량 정보를 읽는 부품 |
| 권한 | 앱이 차량 정보에 접근해도 된다는 허락. 허락받은 정보만 읽을 수 있음 |
| 브랜치 | 다른 사람 작업과 섞이지 않도록 따로 떼어 둔 작업 공간 |
| 커밋 / 푸시 | 커밋 = 내 컴퓨터에 저장, 푸시 = 팀 저장소(GitHub)에 올리기 |
| PR (Pull Request) | "제 작업을 합쳐도 될까요?" 하고 팀원에게 검토를 요청하는 것 |
| Room | 앱 안에 표 형태로 데이터를 저장하는 도구 |
| STT | Speech-To-Text. 말을 글자로 바꿔 주는 음성 인식 기능 |
| LLM | ChatGPT 같은 문장 생성 AI |
