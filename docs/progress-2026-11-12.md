## 1. 계획 줄이기

처음 계획에는 깜빡이 확인, 주차 실력 분석, AI 비서(Gleo) 연동 등 기능이 많았습니다. 시간이 부족해서 **"속도"만으로 동작하는 최소 기능**으로 줄였습니다.

**남긴 기능**

- **운전 중**: "주행 시작" 버튼을 누르면 1초마다 속도를 기록합니다. 어려웠던 순간에는 메모를 남깁니다.
- **운전 후**: 속도 변화를 보고 **급출발, 급가속, 급감속**을 찾아 점수를 매기고 "잘한 점 / 연습할 점"을 보여 줍니다.
- **여러 번 운전한 뒤**: 자주 나오는 약점을 보고 연습 과제(예: "3초 세면서 천천히 출발하기")를 냅니다.

**뺀 기능** (시간이 남으면 다시 검토)

- 깜빡이 안 켜고 회전, 주차 실력 분석, 백그라운드 기록, 음성 안내, AI 비서 연동, 지도 표시 등

자세한 내용은 [driving-feedback-plan.md](driving-feedback-plan.md)에 있습니다.

## 2. 개발 도구 설치

| 설치한 것 | 쉽게 말하면 | 상태 |
|---|---|---|
| Android Studio | 앱을 만드는 프로그램 | ✅ |
| Android SDK 34 | 앱을 만들 때 필요한 부품 상자 (Android 14용) | ✅ |
| Pleos 에뮬레이터 | 컴퓨터 안에서 돌아가는 **가상 자동차 화면** | ✅ 설치됨, 가상 기기는 아직 안 만듦 |
| JDK 17 | Android Studio가 앱을 조립할 때 쓰는 도구 | ❌ Android Studio 설정에서 받아야 함 |

### ⚠ 발견한 문제: 폴더 이름에 한글이 있으면 앱이 안 만들어짐

- 지금 프로젝트는 `C:\Users\신가인\Desktop\...`에 있습니다. 앱을 조립하는 도구가 **경로에 한글이 있으면 작업을 거부**합니다.
- **해결 방법**: 프로젝트를 `C:\Android\pleos-app-challenge`처럼 영어로만 된 폴더에 다시 받아야 합니다.
- 다른 팀원도 Windows 사용자 이름이 한글이라면 같은 문제가 생길 수 있습니다.

## 3. 사전 점검

본격적으로 만들기 전에 "이게 정말 되는지" 두 가지를 확인하기로 했습니다.

| 점검 항목 | 결과 | 의미 |
|---|---|---|
| **V1. 차의 속도를 앱에서 읽을 수 있나?** | ⚠ **된다고 가정** | 가상 자동차가 아직 준비되지 않아 직접 확인은 못 했습니다. 일정상 된다고 보고 다음 단계로 넘어갔습니다. **나중에 반드시 실제로 확인해야 합니다.** |
| **V2. 음성 인식(말하면 글자로 바꿔 주는 기능)을 쓸 수 있나?** | ❌ **못 씀** | "방금 좌회전 어려웠어"라고 말로 메모하는 기능은 쓸 수 없습니다. 다른 메모 방법이 필요합니다. |

### 사용할 수 있는 차량 정보 (받은 권한 목록)

주최 측에서 받은 목록에 따르면 아래 정보를 앱에서 쓸 수 있습니다.

- **주행 관련**: 주행 거리·시간, 브레이크 페달을 밟았는지, 핸들을 얼마나 돌렸는지, 크루즈 컨트롤
- **안전 관련**: 타이어 공기압 부족, 안전벨트 미착용, 엔진오일·브레이크오일 경고 등
- **조명 관련**: 깜빡이(방향지시등), 전조등, 실내등 등

**주의할 점**

- 이 목록에는 **"차 속도"가 없습니다.** 속도는 Pleos가 아니라 Android 기본 기능으로 읽기 때문에 목록에 없는 것일 수도 있습니다. 우리 앱에서 쓸 수 있는지는 확인이 필요합니다.
- 반대로 **깜빡이·핸들·브레이크 정보는 쓸 수 있다는 게 확인됐습니다.** 그래서 뺐던 "깜빡이 안 켜고 회전" 기능은 시간이 남으면 다시 넣을 수 있습니다.

## 4. 데이터 저장 공간 만들기

앱 안에 **엑셀 같은 표 6개**를 만들었습니다. 운전 기록, 분석 결과, 퀘스트가 모두 여기에 저장됩니다.

| 표 이름 | 무엇을 저장하나 | 누가 채우나 |
|---|---|---|
| Trip (주행) | 언제 출발하고 언제 끝났는지, 몇 km 달렸는지 | 운전 중 파트 |
| TripSample (속도 기록) | 1초마다의 속도 | 운전 중 파트 |
| DrivingNote (메모) | 운전자가 남긴 "어려웠던 순간" | 운전 중 파트 |
| TripEvent (위험 순간) | 급출발·급가속·급감속이 언제, 얼마나 심했는지 | 운전 후 파트 |
| TripReport (리포트) | 한 줄 요약, 잘한 점, 연습할 점, 점수 | 운전 후 파트 |
| Quest (연습 과제) | 과제 이름, 이유, 진행도 | 퀘스트 파트 |

**왜 이게 먼저 필요한가요?**
세 파트(운전 중 / 운전 후 / 퀘스트)는 이 표를 통해서만 정보를 주고받습니다. 표 모양만 먼저 정해 두면 **세 명이 서로 기다리지 않고 동시에 개발**할 수 있습니다.

- 이 작업은 `chore/add-room`이라는 작업 공간(브랜치)에 저장했습니다. **아직 팀 저장소에 올리지 않았습니다.**
- 실제로 앱이 문제없이 만들어지는 것까지 확인했습니다.

## 5. 정해야 할 것

| # | 질문 | 추천 |
|---|---|---|
| 1 | 음성 인식을 못 쓰는데, 운전 중 메모는 어떻게 남기나요? | 화면에 **"좌회전 / 주차 / 차선변경 …" 버튼**을 두고 한 번 누르면 기록 |
| 2 | 가상 자동차가 안 되거나 속도를 못 읽으면 발표 때 어떻게 보여 주나요? | 미리 만든 **가짜 주행 데이터를 재생하는 기능**을 다시 넣기 (계획서에서 빠진 상태) |
| 3 | 리포트 문장을 AI(LLM)로 만들기로 계획서가 바뀌었는데, 어떤 AI를 어떻게 쓰나요? | 우선 **정해진 문장 틀**로 만들고, 시간이 남으면 AI로 다듬기 (AI는 인터넷 연결·API 키가 필요할 수 있음) |
| 4 | 데이터 저장 공간 작업을 팀 저장소에 올리고 검토를 요청할까요? | 올리고 바로 검토 → 합치기 (이게 합쳐져야 다른 파트가 시작 가능) |

## 6. 다음 할 일

1. 프로젝트를 영어 이름 폴더로 옮기고, Android Studio에서 JDK 17을 설정합니다.
2. 데이터 저장 공간 작업을 팀 저장소에 올리고 검토받아 합칩니다.
3. 세 파트가 동시에 개발을 시작합니다.
   - **운전 중**: 주행 시작·종료 버튼, 1초마다 속도 기록, 메모 버튼
   - **운전 후**: 급출발·급가속·급감속 찾기, 점수, 리포트 화면
   - **퀘스트**: 약점 찾기, 과제 고르기, 진행도 표시
4. 가상 자동차에서 속도가 정말 읽히는지(V1) **실제로 확인**합니다.
