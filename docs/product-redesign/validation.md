# 구조와 네 가지 시연 검증

검증일: 2026-11-14. 기준은 현재 브랜치의 Debug APK이며 Pleos_Home_2_1, Android user 10에서 실행한다. 사용자 `trips.db`를 삭제하거나 앱을 제거하지 않고 `install -r`로 갱신한다.

## 자동 검사

`ProductSmokeRunner`는 별도 `product-validation.db`만 사용한다. 새 빈 DB로 시작하여 네 화면을 열어도 Trip/포인트가 생성되지 않는 것을 먼저 확인한다. 다음 네 시연에 명시적으로 가상 경과 시간을 넣어 끝까지 검사한다. 이 빠른 검사는 실제로 수 분간 기다렸다는 의미가 아니다.

| 시연 | 이동 거리 | 확인한 완료 증거 | 지급 포인트 |
| --- | ---: | --- | ---: |
| 한 차로 변경 → 우회전 | 약 192.31m | LANE_CHANGE, INTERSECTION | 300P |
| 오른쪽 한 차로 변경 | 48m | LANE_CHANGE | 200P |
| 3차로에서 우회전 | 약 130.20m | INTERSECTION | 100P |
| 후진 주차 | 약 21.87m | PARKING | 100P |

각 시연에서 Trip 종료·거리·속도 샘플·피드백·정확한 증거 종류를 읽어 검증한다. 종료 후 tick을 열 번 더 호출해도 중복 완료나 보상이 없다. 안전거리·출발 점검을 자동 성공 처리하지 않는다.

별도로 한 차로 변경은 실제 경과 시간으로 재생한다. 퀘스트 탭으로 이동해도 같은 tripId의 위치가 진행되고, 일시정지하면 멈추며 재개 후 완료된다. 이때까지 총 5회 연습/6개 증거/900P를 검증한다. DB를 닫고 다시 연 후에도 동일하다. 초기화하면 현재 0P/0회가 되고 지난 주행의 피드백·보상 사건과 개인 프로필은 유지된다.

프로세스 종료 복구는 start만 하고 close하지 않은 별도 미완료 연습으로 검사한다. 다음 컨트롤러에서 INTERRUPTED로 마감되고 새 완료/보상이 생성되지 않아야 한다.

검사 실행 결과와 화면은 앱 내부 `files/product-validation/proof.json`, `*.png`로 남는다. 완료 화면은 Room의 거리/시간/증거/보상/TripReport를 읽으며 Figma 예시 수치를 사용하지 않는다.

## 빌드

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug
```

90개 단위 테스트 통과, lint 오류 0개. 경고는 의존성 업데이트, draw 중 객체 생성, XML 미사용 생성자, 번역/앱 아이콘 등의 후속 정리 항목이다. 관련 버전을 임의로 올리지는 않았다.

`ScenarioSpeechGateTest`는 네 시연에서 작은 핸들 변화가 반복 발화로 이어지지 않는지 확인한다. 최소 6초 간격, 단계당 한 번, 이전 음성 재생 중 끼어들지 않기, 일시정지/미연결에서 발화하지 않기, 지난 단계의 안내를 뒤늦게 읽지 않기도 검사한다. 화면의 핸들 문구는 곡률 변화 대신 행동 단계에 묶는다. 실제 조향량으로 보정하지 않았다는 표시를 지도/주차 화면에 제공한다.

실시간 차로 변경 검사에서는 Pleos TTS를 실제로 켜고 SDK의 PLAYBACK_STARTED가 1~2회인지, PLAYBACK_DONE 콜백이 있는지도 검증한다. 실제 횟수는 함께 저장한 `proof.json`의 `pleosSpeech`에 기록한다.

## 화면 확인

빈 퀘스트/피드백, 지도, 주차 가이드, DRIVE CLEAR를 에뮬레이터에서 확인했다. Figma는 배치·색만 참고하고 차량·캐릭터·아이콘은 자체 벡터 그래픽을 사용한다. 핸들은 사용자 요청에 따라 이전 동적 렌더링을 사용한다. 검정/노랑 완료 화면의 0.192km·초 단위 시간·완료 퀘스트·포인트는 해당 연습의 저장 값이다.

## 한계

자동 검사 성공은 실제 차량의 차로 변경/주차 성공이나 운전 안전성을 검증한 결과가 아니다. 실제 주행 코칭·차로/조향 검증·AAOS 주행 UX 승인은 추가 개발이 필요하다. OEM 좌측 Driving View와 공조/상태 바는 시스템 UI이므로 Figma 예시 속도·시간·아이콘과 다를 수 있다.
