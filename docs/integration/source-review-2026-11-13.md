## 문서 사이에서 달라진 요구

2026-11-11 통합안은 이전 정의서의 변경 사항을 명시한다. 충돌 시 통합안과 이후 사용자가 지정한 앱 이름·화면·시연 요청을 기준으로 삼는다.

- 기술별 단계는 `STARTER → DRIVER → PRO → MASTER`, 전체 운전자 레벨은 별개다. 기존 구현의 `FIRST~FOURTH` 및 `STARTER/DRIVER/MASTER` 전체 레벨은 레거시 체험 모델이므로 최신 기획과 완전히 같다고 쓰지 않는다.
- 기본 6개와 확장 2개로 총 8개 퀘스트. 야간·악천후는 향후 추가다. 이전 퀘스트 문서의 확장 분류와 차이가 있다.
- 출발 전 예습·오늘의 목표·다음 도전 예약을 권하지 않는다. 복습은 도착 후 또는 모바일에서 제공한다. 기존 브랜치의 목표 선택·예습 화면은 실험 화면으로 남아 있으며 최신 제품 흐름으로 정리할 후속 항목이다.
- 차량 데이터만으로 판정하기 어려운 항목은 자기 평가를 복습 참고로 쓴다. 데이터 누락은 성공도 실패도 아닌 무효다. 속도나 깜빡이만으로 실제 차로 이동·안전 성공을 확정하지 않는다.
- 실제 승급은 최근 성공률, 최소 횟수, 서로 다른 주행일 조건을 함께 본다. MASTER는 사용자 확인을 받는다. **현재 시연의 짧은 1/3회 단계 전환은 실제 승급 알고리즘이 아니다.**
- 통합안에서는 도움을 다시 받아도 단계와 레벨을 내리지 않는다. 예전 퀘스트 문서에는 도움 복원 시 단계 표시를 낮추는 설명이 있어 차이가 난다. 통합 구현은 누적 진행을 지우지 않고 자세한 도움만 복원한다.
- `LAN-01~03`, `INT-01~10`, `PRK-01~16`, `PRE-01~05`, `END-01~04` 등 공통 CASE ID를 안내·기록·복습에 사용한다. 기존 `SituationKind.id`는 호환성 때문에 보존했다. 정확한 CASE 번호 이관은 두 정의서의 상세 CASE 대조 후 진행해야 한다. 신호 종류를 모르는 우회전을 임의로 `INT-04`로 기록하지 않는다.

## 이번 통합에서 구현한 연결

주행 시나리오가 시작되면 하나의 tripId를 만든다. 같은 ID로 속도 샘플, 상황 이벤트, 메모, 완료 근거, 리포트를 저장한다. 퀘스트와 코치 설정도 같은 Room DB에 저장하며, 저장된 단계에 따라 다음 안내량을 선택한다. 어려웠던 상황을 기록하면 해당 기술의 도움을 다시 자세히 제공한다. 현재 범위는 기존 시나리오용 퀘스트이며, 개인 실차 성공으로 합산하지 않는다.

## 남은 제품 범위

모바일 앱·공통 계정·서버 동기화, 실제 차량 데이터 기반 8개 퀘스트 전체 판정, 최신 성공률·주행일 승급, CASE별 복습 콘텐츠, 온보딩 3문항, 첫 경험 배지·공유 이미지·스티커 졸업은 미구현이다. 로컬 Room 통합 완료를 차량·휴대폰 간 DB 동기화 완료로 표현하지 않는다.

SDK 권한·차종 지원이 확인되지 않은 사각지대, 차간 거리, 주차 센서, 도로 신호는 가정으로만 남긴다. 통합 기획안도 해당 데이터의 제공을 가정한 설계이므로 실제 API 검증과 구분한다.
